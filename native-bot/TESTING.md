# 构建与验证

自动化检查在 Java 25、Minecraft 26.2 及 README 列出的依赖下执行。准备 `libs/carpet.jar` 后，在本目录运行 `./gradlew build`（Windows 为 `gradlew.bat build`）。

## 自动化测试范围

`src/test/java/com/eunsearch/courier/` 包含 18 项 JUnit 测试：

- `InventorySafetyTest`：15 项，覆盖同色潜影盒内容匹配、实际交货计数、走道边界、保留需求数量、箱满时保留物品、满背包临时空主手及异常恢复、副手不覆盖、不可堆叠物品和拒绝槽位、1728 个散货分批、中文可复制完成文本、负坐标区块边界。
- `BotSuggestionsTest`：3 项，覆盖标签、物品、数量和收货假人参数补全，以及补全替换范围。

报告输出在 `build/reports/tests/test/index.html`。这些测试不启动真实服务器，不能替代 Minecraft 寻路、Carpet 登录或红石回收机器的现场验收。

## 自己仓库的验收步骤

在配置好走道和工作站的测试世界中：

1. `/search mis 钻石` 核对 EunSearch 能找到来源；`/eunfetch recovery` 核对盒子箱、散货潜影盒、音符盒的实际目标。
2. `/botSearchChest mis 钻石 1` 验证散货取物、交货、收货假人下线及可复制指令。在收货点召回该假人，核对实际背包。
3. 选取只存在于箱内潜影盒的物品，验证搬盒、放盒、取出需求数量、挖回、交货和盒子存回回收箱。
4. 分别准备背包已有不足/足够/超额目标物品和无关物品，核对只补差额、只交付需求数量，其余走回收流程。
5. 测试超过 1728 个散货的回收：机器自动收盒并补空盒，两批间至少间隔 2 秒；全部回收结束才触发音符盒。实际容量按物品堆叠上限计算。
6. 另用 `drop` 配置验证固定站位、朝向与落点确认；不要沿用其他仓库的示例落点。
7. 测试停止任务、移除工作假人和越出允许区块；检查旧任务没有继续执行，按配置回到待机点，核对背包与任务 JSON。

使用专用测试收货假人名，避免与已有玩家数据混用。库存核对应包括来源容器、Courier、处理中潜影盒、收货假人和回收容器；不要只以聊天里的成功文字判断完成。

本目录不发布实服任务原始记录、部署日志或 spark 采样。仓库现有 GitHub Actions 只构建 `mod/`；本模组的测试需要上述独立构建步骤。
